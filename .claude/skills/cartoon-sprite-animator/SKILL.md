# Cartoon sprite animator

A character drawn as a **puppet made of parts** (head, torso, limbs, tail, props), posed by numbers for
every frame and rendered as clean vector art. Because every frame is drawn by the same code from the same
parts, the character stays on-model across all frames, and the quality can be measured instead of judged
by eye. Everything is free and runs locally; no image generators, no paid services.

Worked example: Ratislav, a rat swordsman (4 animations, 33 frames, QA PASS). The scripts in this skill
are that project's final code, so they double as the example and as the starting point. Two looks:

- **Drawn look — use this by default** (`scripts/drawn/`, project `v2/`): the figure is drawn like a
  storybook illustration — one even pen line around the whole silhouette, inner lines only where a nearer
  part really passes in front, body and head melted into one soft form, painted backgrounds without
  outlines. Built after the user rejected the sticker look as "a bunch of shapes stacked on each other".
- **Sticker look** (`scripts/`, project root): every part has its own thick outline (Adventure-Time-like).
  Reads as assembled shapes; use only when that is explicitly wanted.

Copy the folder of the chosen look and change the character.

**Before animating, read `references/animation-standard.md`**: the working loop, the twelve principles
as checks on rendered frames, game feel (attack phases, hit-stop), and the rules for hands, props, faces
and scenery that the Ratislav reviews produced.

Companion skills (installed by the kit's `install.py`, from their authors): `2d-character-rig-animation`
(rig contract and defect vocabulary), `character-design-continuity` (character bible for a new design),
`animator-traditional`, `game-development` and `follow-through-overlapping` (animation principles),
`find-skills` (search for more). This skill is the hands-on toolkit; they are the theory.

## What it produces

| Output | Use |
| --- | --- |
| `out/<name>_atlas.png/.json` (+ `@2x`) | every frame on one sheet, Aseprite-hash JSON: per-frame duration, frameTags (incl. sub-tags such as `jump_rise`), anchor, loops, walk speed. Loads in Phaser (`load.aseprite`) and PixiJS (Spritesheet). |
| `out/strips/<name>_<anim>.png` | one horizontal strip per animation |
| `out/svg/<anim>/*.svg` | vector source of each frame |
| `out/gif/*.gif` + showreel | previews in a little scene (walk scrolls the ground exactly in step) |
| `out/model_sheet.png`, `out/rig.json` | character bible (pose, expressions, palette, numbers) and rig manifest |
| `out/qa/report.txt`, `out/qa/contact_*.png` | automatic checks + contact sheets with a ground guide |
| `out/web/*.png` + `templates/demo.html` | playable side-scroller page (canvas game, keycap controls, filmstrips) |

## Requirements (all free)

```bash
python3 -c "import fitz, PIL, shapely; print('ok')"
```
If that fails: `pip3 install --user "shapely>=2.0" "pymupdf>=1.23" "pillow>=9"` (all free; shapely is BSD;
on Windows use `py -m pip install --user ...`). Run your own scripts **without** `python3 -I` (isolated mode
hides the user site-packages where PyMuPDF lives). Commands below say `python3`; on Windows use `py`.

## Workflow

1. **Set up.** Copy `scripts/drawn/*.py` (or `scripts/*.py` for the sticker look) into `<project>/rig/`.
   `build.py` writes into `<project>/out/`.
2. **Design brief first** (write it down, show the user if they care about the look): silhouette,
   2–3 signature features, palette of ≤ 12 named colours (+ a darker "far side" shade for limbs behind
   the body), proportions. The cartoon look comes from: big round head, simple shapes, one uniform thick
   outline (2.5–3 px at 1×), rubber-hose limbs, pastel fills, small dot eyes.
3. **Character module** — start from `ratislav_soft.py` (drawn look) or `ratislav.py` (sticker look) and
   keep its structure:
   - constants: `CELL` (256), `GROUND` (236), `HIP_REST`, `ANCHOR` (ground point under the hip),
     `LINE`, limb lengths/widths, foot geometry (`SOLE`, `HEEL_PT`, `TOE_PT`);
   - `PAL` palette; body part outlines in **torso space** (origin at the hip, y down);
   - a `Pose` dataclass with every control (hip, lean, squash, head tilt, ears, hand/foot targets,
     bend signs, tail/scarf phase, face states, prop angle, fx list);
   - `draw_pose(pose) -> (svg, info)`; `info` must report each limb's stretch and the leg contact data,
     because the QA reads it.
   Rename the file and update the `import ... as R` lines in `anims_soft.py`, `build.py` and `look.py`
   (sticker look: `anims.py` and `build.py`), and the `ratislav_` file prefixes in `build.py`.
4. **Animations** in `anims_soft.py` / `anims.py`. Each function returns a list of `dict(pose, ms, tag, lift)`;
   `lift` moves the character only in previews — sprite cells stay in place so the game does the physics.
   - **Walk is procedural**: during stance a planted foot moves backwards at exactly the ground speed
     (heel rock → flat → toe roll), swing is an eased arc. Ratislav: 8 frames × 83 ms, stride 48,
     96 px per cycle = 12 px per frame.
   - **Other actions are pose-to-pose keys**: anticipation → action → hold → settle. Use one shared
     stance (`STANCE_F/B`) for every grounded pose so switching animations never pops.
   - Ratislav timings that read well: idle 8 × 150 ms (breath, ear twitch, one blink); jump 9 keys
     70/90/60/70/80/130/80/90/110 ms with sub-tags start/rise/apex/fall/land; attack 8 keys
     80/70/110/50/60/110/80/80 ms with the hit on frame 4 (swoosh fx baked into frames 3–5).
5. **Build and check**: while iterating, `python3 rig/build.py --quick` (drawn look, about a minute:
   frames, sprite sheets, checks); at the end the full `python3 rig/build.py` (several minutes; the
   sticker look has only the full build, ~25 s). Read `out/qa/report.txt` — it must end with
   `RESULT: PASS`. Then **look**, with the Read tool, before saying anything about quality:
   `python3 rig/look.py closeup idle:0 walk:2 attack:4` (5x crops of the near hand plus the face),
   `python3 rig/look.py anim attack` (contact sheet + stretched limbs), `python3 rig/look.py scene attack:4`
   (the frame in the painted scene), and finally the GIFs and `out/model_sheet.png`.
6. **Fix by defect class** (names from the rig skill):
   - *stretch* (limb > 1.001 of its length) → move the hand/foot target closer or the joint;
   - *slide* (planted foot moves) → stance ankles must come from the shared stance or `stance_ankle`;
   - *pop* → two adjacent frames disagree on a shared value; *loop hitch* → `pose(p)` and `pose(p+1)`
     must render identical SVG (the QA compares the strings);
   - *flip* → knee/elbow bend sign is fixed per limb (`bend_f/bend_b`), never let it change sign;
   - *occlusion* → fix the draw order in `draw_pose` (far limbs → body → near limbs → near prop → fx);
   - a prop crossing the face or stuck in the ground → change the prop angle in that key.
7. **Demo page** (optional, recommended): `build.py` also writes `out/web/` (backdrop 1400×400 units
   with the ground at 340, a 96-unit ground tile whose period equals one walk cycle of travel, the
   dummy, a dust puff). Copy `templates/demo.html` next to the `@2x` atlas, the web PNGs and the model
   sheet. Update the `ANIMS` block in its script (frame starts, `ms` lists) and verify it against the
   JSON — every `from`, duration and 6-column cell rect must match. The game moves the character at
   `WALK_SPEED = 12 / 0.083` units/s so the feet keep pace with the ground.
   The page has no doctype on purpose (Artifact pages get one at publish); for local viewing prepend
   `<!doctype html><meta charset="utf-8"><meta name="viewport" content="width=device-width,initial-scale=1">`.

## Drawn look: how `inkkit.py` works and what made it read as drawn

- `Ink.part(geom, fill, shade, seams)` is called far → near. Each part's inner line = its boundary ∩ the
  area already covered (shrunk 0.5 px), minus `seams` discs where it grows out of the earlier part (hip,
  wrist, ear root). Lines drawn earlier are clipped by every later part. At the end one line goes around
  the union of all parts; it is heavier on the shadow side (a 1 px offset rim), which reads as pen pressure.
  Inner lines are tapered pen strokes, untapered where they meet the silhouette.
- Melt blobs into one form with `soften(geom, r)` (buffer out, then in) plus a filler blob at the nape —
  a separate outlined head is what makes a figure look assembled.
- Face hierarchy (the most visible mistake in v1): the nose is drawn first, then 2 whiskers that grow
  from the muzzle just **below** the nose and fan forward without touching it, as Bézier curves tapered
  from root to tip (`ink.line(pts, w, taper=(False, True))`). Whiskers starting behind the nose read as
  antennae sticking out of it (rejected by the user twice). The mouth is a short line starting on the
  underside of the snout; open mouths are cut inside the muzzle with a thin rim; no teeth.
  Collars/scarves: band = body strip minus the head, so the chin stays in front; the near arm is drawn
  before the band so its root tucks under it.
- A hand holding a prop is a **mitten fist closed round the grip** (`_fist` in `ratislav_soft.py`): a
  rounded box lying along the grip, drawn over the grip and the arm end, two finger creases on the
  curled-finger side and the thumb edge on the other. The grip shows on both sides of the fist, with a
  small pommel at its end and a slim guard across the blade. A round ball "hand" on the grip plus a ball
  pommel read as a blob stuck to the sword.
- Big heads mean short reach: keep props below the face. For a wind-up behind the head use the
  `arm_behind` pose flag (near arm + sword + hand drawn before the body) and draw slash trails **under**
  the character (`Ink.svg(over, under)`), never across the face.
- Shade = the part minus itself shifted toward the light (`shade_of`), one flat darker colour.
- Painted scenery (`scenery.py`): crisp fills, no outlines and **no blur** — the blurred first version
  was called "super blurry". Depth comes from colour instead: every hill, cloud and tree crown gets a
  lighter band on the side facing the light and a darker one on the side turned away (the shape minus
  itself shifted, lit from the same side as the character), flat-bottomed clouds, little woods peeking over
  the far ridge, a valley-mist gradient (Pillow) between the ridges, a faint paper grain (amount ~0.1).
  `sky(..., wrap=True)` makes the web backdrop seamless (a whole number of waves across the width, scattered
  items also drawn at x ± width). Only props a character touches (the dummy) are inked, so they sit in his layer.
- "In the style of <famous cartoon>": take the general traits (soft round forms, thin even line, pastel
  fills, painted backgrounds), design an original character, and keep the brand name off published pages.
- Cost: shapely makes a frame ~1–1.5 s; the full build takes several minutes on a busy machine.

## Changing the art style

Keep the rig contract — `Pose`, `draw_pose(pose) -> (svg, info)` with `stretch`, leg contact data,
`hand_f` and `face` in `info` — and the animations, checks, build and `look.py` keep working. Then change:

- **Palette** (`PAL` in the character module, colours at the top of `scenery.py`).
- **Line**: `LINE` width, `Ink(w_out, w_in, weight)` for outline, inner lines and pen pressure, or the stroke
  code in `Ink.svg` for a different line treatment.
- **Shading**: the `shade_off` offsets (they set the light direction; the scenery must use the same side).
- **Forms**: the ellipses and blobs in torso and head space, the `soften` radius (how melted the forms are),
  limb lengths and widths, hand and foot shapes, the face states, the props.
- **Scenery**: shapes and colours in `scenery.py`; keep the ground period equal to the walk travel.

A pixel-art look should be reachable by rendering small and quantizing to a palette with Pillow and
nearest-neighbour upscaling; that path is untested here, so prove it on close-ups first. Re-run the whole
loop after a style change: a new style needs its own close-up review.

## Key techniques inside `svgkit.py`

- **Outline groups** (`Canvas.group`): draw every shape's stroke at double width first, then all fills
  on top → one uniform outer outline, no lines where parts of the same group overlap.
- **Rubber-hose limbs** (`noodle`): a quadratic Bézier whose control point is solved by bisection so the
  curve length always equals the limb length — limbs bend, never stretch.
- **Strands** (`strand`, `ribbon`): tapered tails/scarves of fixed length with a travelling wave; drive
  the phase from the animation phase so loops close.
- `clip_convex` (Sutherland–Hodgman) for belts and hems; `smooth_closed/open` (Catmull-Rom) for organic
  shapes; `Affine` for torso/head spaces.
- `rasterize` renders SVG through PyMuPDF; `save_gif` uses one shared palette (no dither) so the colours
  do not flicker; `contact_sheet` adds labels and a ground guide.

## Gotchas

- Scene decorations in a looping GIF must repeat with the walk travel, or the loop jumps. The drawn
  Ratislav travels 48 px per cycle, so its walk GIF shows two cycles over the 96 px ground period.
- PyMuPDF does not render SVG gradients (they come out black); paint gradients and blur in Pillow.
- Pillow `alpha_composite` refuses negative offsets; use `scenery.over()` for anything that can start
  off-canvas.
- Demo page for the drawn look: `templates/demo-drawn.html` (view 330 units high with the ground at 280,
  `WALK_STEP = 6`, thumbnail crop and preview numbers already set for a 150-unit-tall character).
- Keep `lift` out of the sprite cells; the JSON anchor is the ground point, games place it on the floor.
- The in-app browser cannot run local HTML files; for testing, add a temporary `python3 -I -m http.server`
  entry to `.claude/launch.json`, open it with `preview_start`, and remove the entry afterwards.
- Published Artifact pages need their images passed as supporting `files`; keep frame data inline in
  the page so it also works when opened from disk.
- Never name a script after a Python standard-library module (`inspect.py`, `random.py`, ...): the rig
  folder is first on the import path, so PyMuPDF imports your file instead and crashes. The review tool
  is called `look.py` for that reason.
- No subagents are needed; both Ratislav builds ran in the main thread.
